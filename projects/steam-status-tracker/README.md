# Steam Status Tracker / Qu’lon

Статический личный сайт: ссылки на профили, текущий Steam-статус, история игр и сети. [Открыть сайт](https://quixylon.github.io/AI/) · [Открыть трекер](https://quixylon.github.io/AI/#tracker/overview).

## Локальная работа

Node.js 24+, без npm-зависимостей и сборки:

```bash
npm run dev
npm run check
```

Локальный адрес — `http://localhost:4173`. Другой порт: `npm run dev -- --port 8080`. Маршрут `/__preview` содержит рамку для проверки макета на ширине 320, 390 и 768 пикселей. Он существует только в сервере разработки и не публикуется.

`npm run check` проверяет JavaScript, JSON, ссылки HTML/CSS, уникальность HTML ID и согласованность статуса с историей, затем запускает регрессионные тесты данных, анимации и обновления Steam. `npm test` запускает только тесты.

## Оформление и движение

Панели используют эффект линзы: один WebGL 1 canvas берёт пиксели фоновой сетки и преломляет их у скруглённых краёв, слегка увеличивает середину, добавляет диффузное размытие и отражение света. Результат копируется в canvas внутри самой карточки: её скругления, парение и наклон применяются браузером один раз. Отдельного полноэкранного контура стекла нет. Узкое отражение следует кривизне края и направлению света от ближайшего курсора. Текст остаётся отдельным чётким слоем. При недоступности или потере WebGL включается матовое CSS-стекло; после восстановления контекста линза возвращается. Старая страница затухает за 110 мс. Карточки нового раздела по очереди выходят из глубины за 680 мс: перспективное смещение от −150 px к нулю, подъём на 20 px и исчезающий блюр. Интервал между стартами — 95 мс, общая задержка ограничена 380 мс. Преобразуется каждая карточка, а её линза использует ту же матрицу; парение и наклон продолжаются независимо. Панели за пределами экрана проявляются при прокрутке. Быстрые переходы отменяют устаревшую навигацию и отложенный перенос фокуса. Переключение вкладок стрелками сохраняет фокус на выбранной вкладке. Наклон, масштаб и парение не сбрасывают друг друга. Нажатия на элементы управления дают короткий упругий отклик. Преломление ограничено шириной края и плавной синусоидой; добавлены диффузное размытие, отражение по Френелю и направленный блик по нормали поверхности. Круглая подсветка поверх карточек удалена. Исходные принципы: [Apple, Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) и [liquidGL](https://github.com/naughtyduk/liquidGL). Веб-реализация преломляет живой фон, а не использует нативный материал iOS. При выборе амплитуды сохраняется ограничение: выборка не складывается сама на себя, поэтому не должна дублировать точки. Смещение проецируется через ту же матрицу, что и панель; у края экрана оно затухает. Локальное освещение подчёркивает линзу.

Фон — живая сине-бирюзовая сетка с мягким индиго по краям, четырьмя движущимися полями света и вторым мелким слоем точек. Оба слоя следуют одному согласованному полю деформации: широкие волны заметно изгибают ряды, но их малые пространственные градиенты не дают сетке складываться. Курсор усиливает движение и освещение, оставляет затухающий световой след. Яркость образцов следа не суммируется; вихревого стягивания нет. Смещение от взаимодействий ограничено четвертью шага сетки, включая пружинный выброс. Основной радиус точки — до 1,3 px; мягкое свечение рисуется одной переиспользуемой текстурой с прозрачным краем в пределах 10×10 px. Плоских дисков-ореолов нет. Нажатие запускает затухающую волну; одновременно допускается не больше трёх. Касания поддерживаются без блокировки прокрутки. Сила следа зависит от скорости между накопленными образцами, независимо от частоты событий мыши; повторный вход не соединяется со старой позицией. Телефон получает ту же целевую частоту до 60 кадров в секунду, плотность до 2×, силу волн и амплитуду парения, что и ПК. Бюджет фонового canvas — 6 миллионов пикселей, 2400 основных точек и до 1200 мелких; WebGL-контекст и исходная текстура общие, невидимые карточки не отрисовываются. В скрытой вкладке отрисовка останавливается. Системное уменьшение движения оставляет статичную линзу, а повышенная контрастность и уменьшение прозрачности делают поверхности непрозрачными.

## Звуки и кот

Наведение и нажатие озвучиваются короткими тихими синтезированными тонами, без скачивания аудиофайлов. Браузер разрешает их после первого клика или нажатия клавиши. Переключатель «Звуки» сохраняет выбор; он также отключает мяуканье. Один AudioContext, ограничение четырьмя одновременно звучащими интерфейсными нотами и освобождение узлов после завершения. Кот остаётся эмодзи: кнопка получила заметную область нажатия, реакцию на поглаживание и короткое «мур». Уменьшение движения соблюдается.

## История активности

Игровые сессии и сеть — независимые списки. Фильтр сети не скрывает игры; запуски игр не дробят непрерывный период того же сетевого статуса. Записи сгруппированы по дням, новые находятся сверху, интервал времени и длительность показываются отдельно. Статусы сети показаны контрастными текстовыми метками: мятный онлайн, серо-голубой офлайн, янтарный «отошёл», лавандовый сон. Текущий период отмечен словом «Сейчас». Исходный JSON истории при группировке не изменяется. Отдельный список «Запущенные игры» объединяет наблюдённые игры и библиотеку Steam с ненулевым игровым временем, поддерживает поиск. Общее время и время за последние 14 дней берутся из Steam; история сессий содержит только наблюдения сборщика. Если Steam возвращает время последнего запуска, оно показывается отдельно. Счётчики не превращаются в выдуманные интервалы.

## Данные

- `bio.json` задаёт имя, описание и социальные ссылки. Начальная HTML-разметка повторяет их для работы без JavaScript; при изменении ссылок обновляйте оба файла.
- Steam API вызывается только в GitHub Actions. Браузер раз в минуту читает опубликованные `status.json`, `history.json` и `games.json`. Сбой одного из ресурсов остаётся видимым до его успешного обновления; индикатор загрузки учитывает каталог игр. Каталог использует `IPlayerService/GetOwnedGames` и `GetRecentlyPlayedGames`; при отказе одного источника сохраняются ранее полученные игры. Настройки приватности «Данные об играх» могут ограничить ответы Steam.
- История содержит до 500 последних интервалов; в интерфейсе интервалы преобразуются в записи игр и сети. Время показывается в часовом поясе посетителя. Статистика приблизительна: изменения между проверками Steam могут быть пропущены.
- Discord и Telegram пока представлены ссылками. Реального мониторинга этих платформ нет; интерфейс явно показывает «В процессе».
- Существующий внешний счётчик посетителей использует случайный идентификатор в `localStorage`. При недоступности сервиса отображается `—`.
- Данные и ссылка CSRep сохраняются. Автоматического обновления CSRep в этом репозитории нет.

## Публикация

Workflow: [`.github/workflows/validate-site.yml`](../../.github/workflows/validate-site.yml).

1. Pull request проходит `npm run check` без разрешений на публикацию.
2. Изменение сайта в `main`, ручной запуск или расписание обновляют Steam и проверяют проект.
3. Каждый успешный снимок Steam сохраняется коммитом, включая время проверки и каталог; временные сбои API сохраняют последнюю успешную версию.
4. Только прошедший проверку каталог `public` загружается в GitHub Pages.
5. `build-info.json` записывается в артефакт публикации; отдельные коммиты ради отметки сборки не создаются.

Расписание запрашивает запуск каждые пять минут со смещением от начала часа; GitHub может задерживать или пропускать запуски. Интервалы между успешными проверками сохраняются в `status.json`; при разрыве больше 15 минут интерфейс поясняет ограничение истории. Надёжный поминутный учёт сессий требует сборщика с более точным расписанием вне GitHub Actions. Для работы требуются GitHub Pages с источником **GitHub Actions**, секрет `STEAM_API_KEY` и необязательная переменная `STEAM_ID64` (либо `STEAM_VANITY`, по умолчанию `quixylon`). Ключи и `.env` не добавляются в репозиторий.
